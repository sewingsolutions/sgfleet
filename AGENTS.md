# AGENTS.md

## Project

SGFleet LLM inference gateway with dynamic model management, API gateway, user management, and metrics.

## Stack

- SGLang (various models), Docker Compose, Grafana Alloy, Prometheus
- Models stored at `YOUR_MODELS_PATH/vllm_models/` (mounted as `/models` in containers)
- Model config in `models.json`, persisted in SQLite (`admin_db` volume)

## Setup

1. Run `./scripts/init.sh` — interactive host setup (host verification, `.env`, directories, model scanning, Docker Compose launch)
2. Open `http://<LAN-IP>:8000/admin/setup` — first-boot wizard (admin name, base URL, HF token)
3. Copy the generated admin API key (shown once)
4. Log in at `/admin/login`

## Commands

- `docker compose up -d` — start all services
- `docker compose --profile monitoring up -d` — also start Alloy metrics forwarding
- `cd backend && ./deploy.sh` — rebuild + restart backend only
- `cd frontend && ./deploy.sh` — rebuild + restart frontend only
- Model switching via admin UI or `POST /admin/api/models/{id}/toggle`

### Starting a specific model container manually
```bash
docker run -d --name sgfleet-gpt-oss-20b --network sgfleet_default --network-alias sgfleet-gpt-oss-20b \
  --gpus all --shm-size 32g --ipc host --privileged --restart unless-stopped \
  -v YOUR_MODELS_PATH/vllm_models:/models lmsysorg/sglang:v0.5.16 \
  sglang serve --model-path /models/gpt-oss-20b --host 0.0.0.0 --port 30000 [flags...]
```

## Structure

- `backend/` — FastAPI gateway, admin API, model lifecycle (`backend/app/`)
- `frontend/` — React SPA, nginx config, Dockerfile
- `telemetry/alloy/` — Grafana Alloy config (Docker Compose profile `monitoring`)
- `scripts/` — Host initialization & utility scripts
- `models.json` — model definitions (bootstrapped into SQLite on first run)
- `docker-compose.yml` — service orchestration (backend, frontend, monitoring)
- `.env` — infrastructure config only (no secrets); secrets stored encrypted in DB

## First-Boot Setup Wizard

The service returns 503 (`setup_required`) on all gateway and admin endpoints until `/admin/api/system/setup` is called. The wizard at `/admin/setup` collects admin name, base URL, and optional HF token, then generates an admin API key (shown once).

## Secrets Management

- `ADMIN_API_KEY` and `HUGGINGFACE_TOKEN` are encrypted (Fernet) and stored in SQLite
- `SGFLEET_ENCRYPTION_KEY` (generated by `scripts/init.sh`) is the sole key in `.env`
- **If `SGFLEET_ENCRYPTION_KEY` is lost, encrypted secrets cannot be recovered**

## Model Management

Models are defined in `models.json` and bootstrapped into SQLite on first startup. The backend service manages model container lifecycle:

- **Startup**: `main.py` checks setup status; if complete, decrypts admin key and runs `ensure_models_sync()` which starts active models, waits for `/health` (up to 600s), and marks them ready. If setup incomplete, model sync is skipped.
- **Active/Ready**: A model must be both `active` in the DB AND pass the health check before the gateway routes traffic to it.
- **Primary Model**: The first active model gets the `sgfleet-server` network alias.
- **GPU Allocation**: `gpu: "auto"` uses all GPUs; `"0"`, `"1"` target specific GPUs.
- **Switching**: Toggle active flag via admin UI or API → triggers full container sync.

## Backend Key Files

- `backend/app/db.py` — SQLite layer, migrations, model/user CRUD, bootstrapping
- `backend/app/docker_manager.py` — container lifecycle, health-wait, `ensure_models_sync`
- `backend/app/model_registry.py` — in-memory model cache, ready set, endpoint lookup
- `backend/app/gateway.py` — request proxy, per-model routing, rate limiting, auth
- `backend/app/admin_api.py` — admin REST endpoints
- `backend/app/auth.py` — JWT auth, session tokens
- `backend/app/crypto.py` — Fernet encrypt/decrypt for secrets
- `backend/app/main.py` — FastAPI app, startup model sync

## Frontend Key Files

- `frontend/src/api/client.ts` — API client
- `frontend/src/pages/SetupWizard.tsx` — 5-step first-boot setup wizard
- `frontend/src/context/AuthContext.tsx` — auth state
- `frontend/src/pages/ModelsPage.tsx` — model management UI

## Rules

- Always fix lint and LSP errors before considering a task done
- Never manually `docker exec` or restart model containers — use the admin API or UI
- The backend container has Docker socket access to manage model containers
- Database is SQLite at Docker volume `admin_db:/data`
- Metrics flow: backend:8000/api/metrics → Alloy → external Prometheus
- Gateway returns 503 JSON when no model is ready, or auto-drops a model from the ready set on DNS failure
- Gateway returns 503 `setup_required` when first-boot setup wizard has not been completed
- Backend container has GPU device reservations for direct `nvidia-smi` access
- Alloy service is behind Docker Compose profile `monitoring`
